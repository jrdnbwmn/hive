# Lens: Task Walkthrough (default)

**Collect first:** the user's tasks for each screen/flow, as a short
prioritized list (most important first). Take them from the design
doc's Primary tasks if it has them; otherwise ask the user. Don't
invent them.

**Walk each task, highest priority first.** Break it into the concrete
steps the user takes. At each step ask:

1. Will they know what to do here?
2. Will they see the control that does it?
3. Will they recognize it as the right control?
4. After acting, will they get feedback that it worked?

A "no" is a finding, ranked by how badly it blocks the task — a "no" on
the top task outranks the same "no" on a lower one.

Also:
- **Count the steps** for each task. Avoidable steps on the top task
  are P1.
- **Question every required field.** Each one costs completions.
- **Distractions:** anything that competes for attention with the top
  task's path, without helping any listed task, is a finding.
- **Emphasis should follow priority.** The top task's action should be
  the most prominent thing on the screen.
